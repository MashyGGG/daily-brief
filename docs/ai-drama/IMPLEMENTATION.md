# AI 短剧／漫剧专题实现说明

状态：本地实现完成，待部署验证实际邮件。更新日期：2026-10-30。

学习和制作操作见 [PLAYBOOK.md](PLAYBOOK.md)。本文件用于维护代码、调节来源及上线。

## 1. 内容如何进入独立邮件

```text
ai-drama 定时任务（08:10 Asia/Shanghai）
  → 仅采集专题栏目引用的来源
  → 专题历史去重（不消费技术早晚报条目）
  → 时间／栏目过滤、基础排序、当前阶段相关性加权、来源配额
  → 有界正文质量筛选（独立于模型）＋栏目上限
  → 中文摘要＋AI 辅助复核＋结构化制作笔记（模型可用时）
  → 附加当前阶段教材、小练习、完成标准、完整五步路线
  → 归档内容和提醒快照
  → 仅给尚未确认发送成功的收件人发送
  → 保存发送结果，随 archive 一起提交
```

现有邮件 SMTP、密钥、收件人、HTML 格式继续复用。专题是新期次，主题为 `AI短剧·漫剧日报 · 日期`，没有回复邮件头。

## 2. 来源清单与核验

所有资讯 Feed 均为 Google News 搜索 RSS，具体完整 URL 在 `brief.config.yaml`。它是发现入口，原始报道质量仍需读原文判断。

| 配置 ID           | 内容                                         | 发现范围         |
| ----------------- | -------------------------------------------- | ---------------- |
| drama-cn-news     | AI 漫剧或 AI 短剧                            | 中文，查询近两天 |
| drama-en-news     | AI filmmaking 或 motion comic                | 英文，查询近两天 |
| drama-cn-tutorial | AI 漫剧／短剧＋教程／分镜／工作流            | 中文，查询近30天 |
| drama-en-tutorial | AI filmmaking tutorial                       | 英文，查询近30天 |
| drama-cn-models   | 可灵／即梦／万相／混元视频＋视频／漫剧／短剧 | 中文，查询近两天 |
| drama-en-models   | AI video＋model／release／workflow           | 英文，查询近两天 |
| drama-comfyui     | ComfyUI Releases                             | 官方版本 Feed    |
| drama-ltx         | Lightricks/LTX-2 Releases                    | 官方版本 Feed    |

资讯和技术栏各最多 10 条、保留最近 48 小时；教程栏最多 6 条，使用独立的 `lookbackHours: 720`（30 天）窗口，中文和英文教程搜索同步扩大到 30 天。固定教材仍与有发布日期的教程分开。

新增两组直接来源：`drama-comfy-tutorials`（https://blog.comfy.org/feed）和 `drama-hf-tutorials`（https://huggingface.co/blog/feed.xml）。2026-10-30 实测均返回有效 Feed；Comfy 官方 YouTube 频道的 XML 入口返回 404，因此未接入。

- [HunyuanVideo](https://github.com/Tencent-Hunyuan/HunyuanVideo)：旧 Releases 最新条目为 2024-12-03，配置声明保留但不再由专题栏目引用。
- [HunyuanVideo-1.5](https://github.com/Tencent-Hunyuan/HunyuanVideo-1.5)：本次探测 Releases Feed 为空。

这些测量证明入口当时可访问，不证明持续稳定，也不证明模型能力和教程质量已经实测。新增来源前继续检查返回格式、真实日期、频率、正文可读性和归属。

## 3. 相关性、栏目分配与阶段排序

`src/learning/classify.ts` 在去重之前检查文章是否与短剧、漫剧、视频生成、角色、分镜、配音或制作工具有关。聚合新闻要求标题有明确制作主题，不能仅凭摘要里出现 AI 就入选；泛 AI 财经和游戏商业评论不进入专题。官方 Release 来源保持技术更新身份。

栏目不再由发现 Feed 决定：教程信号明确的文章优先进入教程栏；产品发布、模型能力或工具更新进入技术栏；其余相关行业消息进入资讯栏。预测行业走向、普通产品宣布、仅摘要提到 workflow 的文章不因此成为教程。分类是保守的编辑规则，不能替代人工质量审核。

所有专题来源共享给三个栏目，但一篇文章只分到一个栏目。先排除不相关或超出该栏目窗口的候选，再进行重复合并；同文优先保留官方博客等直接来源。选取顺序先保证教程，邮件展示顺序保持资讯、教程、技术。教程 30 天窗口对应的历史去重至少读取 30 天，避免第 15 天重复推荐旧教程。

## 4. 阶段、教材与排序

`src/learning/ai-drama.ts` 保存五阶段定义、每阶段两份教材和关键词：

- observe：概念、案例、分镜入门。
- practice：角色一致性、参考图、单镜头与图生视频。
- pilot：剪辑、旁白、配音、字幕、叙事。
- publish：平台、发布、版权、标识、发行。
- engineer：开源、工作流、部署、显存、推理。

匹配原标题和来源摘要，每命中一个阶段关键词给基础 rankScore 增加 15%，最多增加 45%。不按模型生成摘要排序，保持可复现；不剔除其他阶段的更新，原有每来源配额继续生效。关键词是编辑启发规则，不能保证语义分类完全正确。

教材按专题日期在当前阶段内轮换，两天一循环；日期不改变阶段。邮件明确区分“常青教材”和“今日新闻”，不伪造发布日期。当前阶段只在用户修改配置后变化。

## 5. 制作笔记与降级

`Item.productionNotes` 的可选字段：

| 字段         | 含义                                   |
| ------------ | -------------------------------------- |
| suitableFor  | 适用制作环节                           |
| difficulty   | 原文描述的难度                         |
| requirements | 工具、版本、硬件、许可证等明确前置条件 |
| steps        | 最多 5 步，每步最多 100 字             |
| limitations  | 原文说明的限制                         |
| evidence     | 由代码设置为 fulltext 或 excerpt       |

专题提示词传入当前阶段，要求只提取原文明确内容。`src/learning/content.ts` 再进行类型检查、长度限制、去重和文本清洗，剔除模型生成的链接与 HTML。未知字段不猜测，渲染显示“原文未说明”。

证据类型由实际模型输入决定，模型不能自报“已验证”。所有笔记明确说明“未经本项目运行验证”。这不是对内容事实的自动保证，关键硬件与许可条件仍应回到原文核查。

- 未设置模型密钥／主动停用模型：保留原始摘要和语言，提示详细步骤需读原文；固定教材继续显示。
- 正文抓取失败：以来源摘要整理，明确标识“仅来源摘要”。
- 模型请求失败：该条回退到来源摘要，其他条目和步骤提醒继续发送。
- 无新条目：发送简短状态与学习提醒，不用旧新闻凑数。
- 部分来源失败：明确显示覆盖不足，不把抓取失败当作无更新。

## 6. 自动补跑和手工重发

内容归档在发送前完成，文件仍是 `archive/YYYY/MM/YYYY-MM-DD.ai-drama.json` 与 `.md`。步骤、教材、制作笔记一起保存。

投递状态单独保存在 `archive/delivery/YYYY-MM-DD.ai-drama.json`：

```json
{
  "version": 1,
  "date": "2026-10-30",
  "scheduleId": "ai-drama",
  "recipients": {
    "me-mail": { "status": "sent", "at": "2026-10-30T00:15:00Z" }
  }
}
```

该文件不保存邮箱地址、密钥、错误原文或正文。只有邮件驱动正常返回才写入 sent；skipped 和 failed 都可以在下一次自动运行中重试。

自动运行（cron 或 `--skip-if-archived`）的处理：

1. 没有归档且没有已发送记录：正常采集、整理、归档、发送。
2. 有归档：直接读取它，不重新采集或调用模型。
3. 对已确认 sent 的收件人跳过，其他收件人继续发送。
4. 只更新了发送结果也必须提交 archive，不要求重新生成内容归档。
5. 有已发送记录却缺少归档，或记录不可解析：停止并报错，避免盲目重复发送。

人工直接运行 schedule 或明确 `--from-archive` 是强制重发入口，允许再次发给全部选中收件人。

边界：SMTP 接受邮件与状态写入、git 推送并非原子事务。进程中断、状态提交失败、SMTP 超时但已接受等情况仍存在不确定性。本实现不承诺绝对只投递一次。不要删除状态文件来“修复”未知结果，先查看运行日志与实际邮箱。

GitHub Actions 仍使用现有串行 concurrency 组。手动在本地同时启动多个真实发送进程没有分布式锁，应避免这样操作。

## 7. 操作入口

```sh
# 本地预览：真实采集；不调用模型、不发送、不归档
pnpm brief:ai-drama:preview

# 模型整理计划：只列计划，不发送、不归档
pnpm brief --schedule ai-drama --dry-run --llm-dry-run

# 配置凭证后的真实人工运行（会发邮件）
pnpm brief:ai-drama

# 使用当前专题 cron 自动恢复模式（会发送尚未成功的收件人）
pnpm brief --cron '10 0 * * *' --skip-if-archived

# 明确强制重发某日邮件
pnpm brief --schedule ai-drama --from-archive 2026-10-30
```

不要把最后三条作为本地验证命令随意执行。部署后按照 PLAYBOOK 的上线清单核对真实送达和独立主题。

本次新增测试覆盖：历史去重分组、阶段排序、教材轮换、零条目邮件、提醒快照重发、来源异常、模型制作笔记到各格式渲染、输出清洗、部分失败补发、成功收件人跳过及损坏状态拒绝。

## 8. 首次部署与维护

1. 将工作区实现、手册和生成的 workflow 部署到 main。
2. 核对已有 SMTP 与收件人配置；中文详细整理需要 LLM_API_KEY。
3. 手动预览后再执行真实邮件验收；本地 dry-run 中 stdout 显示 sent 仅表示预览已输出。
4. 外部定时器使用 `10 0 * * *` 作为 cron 输入，按北京时间 08:10 调用；内置 cron 保留作兜底。
5. 查看 Summary、实际邮箱、内容归档及投递状态提交，分别判断这四件事。

08:10 是启动时间；调度延迟、模型耗时与邮件服务耗时会影响到达时间。首次运行后观察耗时，当前 workflow 总上限为 10 分钟。

## 9. 内容质量筛选（2026-10-30）

10／6／10 是上限。每栏最多检查容量两倍的候选（默认合计不超过 52 条），按排序预选后再检查，避免无限抓取补足。检查通过后才使用最终名额；不足时显示实际数量与综合筛选原因，不用过期或低质量内容补足。日志中的 `editorial` 行显示每栏检查、排除和正文获取数量。

- 栏目依据内容判断，不因来自 `-models` 就进入技术栏。商业访谈、财报、融资、行业规模预测归入资讯，经营类报道最多两条并降低排序权重；工具发现源中既无技术更新也无行业新闻证据的内容不再塞进资讯。
- 对资讯增加制作、作品、发布、版权、平台等价值信号要求；排除熬夜健康话题、消费争议及“宝藏资源／全套教程”等资源广告。
- 教程要求正文或摘要中同时出现具体操作和素材、参数、节点、命令、工作流等线索。只有“如何”“指南”的标题不能通过。操作线索不足则排除；实际流程仍需打开原文跟做。
- 非 Release 技术文章要求有明确更新说明；对比评测要求有测试依据。泛工具榜单被排除，明确评测仍需证据。官方来源排序增加 30%；入门阶段优先入门教程，开发类教程降低优先级。难度是关键词预估，并非课程作者认证。
- 对标题明确出现早于当前年份减一的年份的非 Release 内容执行保守排除。例如 2026 年标题中的 2024 旧话题被排除。它不能识别没有标注年份的旧闻，也不推断事件日期。

正文质量检查不依赖模型开关或模型密钥：教程与非 Release 技术候选会尝试正文提取，最多并发四个，单页超时最多六秒，复用已有 URL、跳转、响应大小与正文长度限制。新闻在此阶段只检查来源摘要，官方 Release 保留版本身份。正文获取失败时只依据 RSS 摘要；摘要不足则排除。正文在内存复用，不写入归档。`--llm-dry-run` 不进行这些正文请求，所见结果可能因缺乏正文而少于真实运行。

模型可用时，在同一次摘要调用内输出 `editorialReview` 的三个布尔值：相关性、教程可操作性、技术证据。只有显式 `false` 才会排除对应内容；返回字段缺失、类型不符或模型失败时保留规则筛选结果。模型不会突破窗口、配额或将规则已排除内容重新放回。AI 复核后不自动补位，也不增加模型调用预算。新闻和 Release 仍可按既有模型策略提取正文；已检查的教程、技术正文复用，失败请求不重复抓。

HTML 邮件、纯文本和 Markdown 归档统一显示内容类型、教程预估难度、入选依据、建议行动、来源发布时间及正文／摘要依据。它们属于编辑提示，不是来源事实认证。模型制作笔记新增 `whyItMatters` 和 `nextAction`，只整理来源支持的信息；没有模型时仍显示规则生成的阅读或练习建议。学习路线继续位于末尾。

新增回归覆盖商业访谈、财经前瞻、缺乏步骤的教程、无测试依据的评测、旧年份标题、两条经营资讯上限、正文请求失败、计划模式不抓正文、正文复用、AI 排除以及三个输出格式的一致展示。
